This Source successor lets a verified terminal observation finish its original submitted governed Dot capture. No live file, process, request, provider record or ERP document is changed by this package.

The product delta is three files: aibit_relay.cjs (actual deployed b3 baseline), aibit_dot_observation.cjs (existing read-only observer), and new original_dot_capture.cjs. The original b3 sources are retained under original/. The canonical deployment/windows main JS is older than deployed b3, so selected Git evidence exports preserve the actual baseline without overwriting that unrelated checkout file.

Each entry binds immutable authenticated intake before toolContext append: owner/account/job/thread/Dot URL and full original governance scope/message hashes. Only the existing validated gateway admission receipt enables capture, after actual submission and on the actual internal Chrome target. The active feed root is retained when known. Transport-only stream/channel fields do not change identity. Legacy/non-governed handoffs do not enter this registry.

The existing /dot/observe implementation is reused internally. It verifies the original account, owned thread, current conversation and exact feed-bound AGOV identity; an actual DOM generation/Stop read must also be idle. Its internal callback can settle only the matching admitted target/root/scope. It retains the exact observed response and original scope receipt. No user-supplied terminal proof is accepted. Complete JSON presence alone is insufficient to free a capture.

A private, capture-only wake closes that original read-side CDP session. Session guards prevent reconnect after settlement. The original relayMessage catches only its own private settlement error and returns the actual observed result to the original response producer. The original handoff emits its ordinary complete frame and owns the sole finally/release. The observer never decrements the capacity counter, cancels the model, closes a browser tab, dispatches Send or writes provider state. Wrong, missing, closed or already-settled entries cannot be revived.

Once the existing Dot responseLimitMs is reached, a governed submitted capture invokes this same internal original observer once, within the existing response wait. It creates no interval, background job, API or additional model request. A nonterminal or failed recovery read leaves the original fenced and is not automatically repeated. The existing bounded HTTP/DOM/Core receipt reads remain in force. Normal live feed completion, nongoverned responses, business validation and all Core/Native publication rules are unchanged.

Python receives the original normal complete frame, then follows its normal record_receipt/save_dot_reply/complete_original path. The separate Core recovery change only reaches the existing observer and does not duplicate receipt/publication writes.

Runtime activation is Root-owned under the reviewed drained state and exact old terminal proof; no hot injection is provided. Lost original HTTP acknowledgement remains uncertain and reconciles through the original normal observer/ledger paths. This package is Source and finite fixture evidence, not a completed deployment or a claim that the earlier stale reader's precise cause is known.
