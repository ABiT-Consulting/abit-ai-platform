# Existing abitdot relay: compact context and exact outgoing rejection

Source proposal for four existing Linux relay leaves. No new application, runner, endpoint, polling loop or fallback provider. Root owns activation.

## Runtime fixes

The existing Dot feed reader accepts the compact `IMMUTABLE GOVERNANCE CONTEXT REFERENCE` generated by the existing abit.ai dispatcher. It compares the invocation, run, project/revision, task/revision, actor and packet digest against the fixed preamble, outer server metadata and final verified ERP context. The previous full-packet parser remains supported. Complete context remains available through the existing admitted `context.read` operation. A compact transport changes no business authority.

The existing read-only `/dot/observe` can expose a failed optimistic outgoing post only when the exact visible original envelope matches and its own visible button has the exact label `Failed to send. Click to retry`. It also requires the exact visible ChatGPT length-error dialog, no reply, no response and no generation. A global failure control, another root, hidden control, virtualized original or changed identity cannot supply this proof. The returned `v4_outgoing_rejection` contains the exact original root, scoped admission receipt and failure facts. No earlier baseline/Send facts are invented.

For an empty outgoing feed, automatic capture rejection instead requires an empty idle baseline with no earlier length-error dialog, one known Send attempt and no accepted-message observation or known root. Zero messages alone never establish rejection. Unknown outcomes retain their original fence.

A private original-capture signal wakes only its original handler, which releases its reservation once. The rejection response carries only minimal binding/failure facts, excluding private page body diagnostics. Existing positive reply capture and non-governed relay behavior remain covered.

## Activation boundary

`activate.py` validates the four exact existing source leaves and root-retained original observation. The observation remains explicitly UNRESOLVED; installation itself never classifies it as rejection or completion. It records consistent database backups, closes the existing admission gate to DRAINING, atomically replaces the four leaves, sends one birth-bound Node SIGTERM and closes only the exact original Core-to-Node HTTP socket so the existing HTTP server can drain. The existing watchdog replaces Node. Main, QA, Chrome and other protected processes remain unchanged. All unrelated provider/invocation rows and unresolved lease journals are compared before and after. No original is reset or resent, no database is restored, and no model or ERP action is sent. The controller leaves admission DRAINING for the subsequent reviewed Core source reload.

The older original request does not acquire new in-memory baseline facts through deployment. After activation, one normal authenticated observation may establish row-local failed-outgoing proof for that same original; Core must verify and retain that proof separately before any supported retry.
